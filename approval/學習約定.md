## 2. 教學節奏（GitHub／NotebookLM／陌生專案）

- 一般情況：**一次只給一步**；等使用者回報完成後，再給下一步。

- 組合方式：
  - **Cursor／本 Agent**：結構、路徑、問卷、跑 code、排錯。
  - **NotebookLM**：依使用者上傳來源深讀、摘要、自測、語音摘要。
  - **Gemini 等一般對話**：廣問概念可以；若要與指定教材一致，以 NotebookLM 來源為準。

## 3. NotebookLM 語音摘要提示詞（預設）

產生語音摘要時，提示詞預設使用（可整段貼上）：

```
請用台灣繁體中文，用語與語氣要像台灣日常口語，不要用中國大陸用語、用詞或播報腔。

像媽媽在說故事那樣：溫柔、清楚、好懂，有一點生活比喻，不要像教科書或新聞主播。

對象是完全初學的人。請依序說清楚本章重點流程。
少講參數細節，多講每一步在做什麼、為什麼要做。
最後用一句很白話的話，把整章串起來。
```

設定建議：長度「中」、語言「繁體中文」、來源為當前章節檔案。

## 4A. 目前學習進度（公司簽核系統／本倉庫 Approval）— **現行主線**

- 上游約定庫：`https://github.com/hyi1105/Approval`（SEED 無 push 權限時改寫在 `https://github.com/hyi1105/SEED` 的 `approval/`）

- **Agent 已選定路徑（SEED 執行中）：**
  1. **介面**＝紙本／Teams 風網頁（`approval/docs/`）；本機 HTTP 開啟
  2. **表單引擎**＝JSON schema 驅動渲染（`docs/schema.json`）
  3. **共用資料**＝本機 PoC：`localStorage` shared 區（之後換 SharePoint 清單）

  6. **身分**＝本機切換 user_id（之後 Entra／MSAL）

### 4A.0 產品願景（純對話簽核）

使用者要的不是「再做一套 Power App」，也不是上方表單＋流水線，而是：

| 區塊 | 行為 |
|------|------|
| 主畫面 | **對話框（人）＋系統時間軸（中間穿插）**，像 Cursor 聊天 |
| 欄位 | 對話框內預設欄位／預設值可編（便條底線，非厚按鈕） |
| 系統區塊 | 寄信通知、該關權限、版本變更敘述、隱私是否進共用庫…夾在對話框之間 |
| 簽核關卡 | 以系統區塊呈現 Approver 狀態與權限（非獨立流水線畫布） |
| 按鈕 | 送出掛在申請人表單框；核准等掛在簽核操作 |
| 欄位分層 | shared 進共用；personal 只在申請人自己的框；別人畫面沒有那格 |
| 欄位型態 | 文字／數字／下拉／是非／人員（schema 驅動） |

### 4B.2 三小時最大化學習／演示行程（全部 11 章）

目標：三小時內 **每一章都學到「問題→做法→產出→1 個關鍵詞」**；先架構再逐章填空。  
深度上限：不跑完整訓練／不部署；以 README＋NotebookLM＋我整理為主。

時間預算：180 分 ≈ 架構 25 分 ＋ 11 章×12 分（132）＋ 收斂演示 23 分。

| 時段 | 分鐘 | 做什麼 | 產出 |
|------|------|--------|------|
| Block 0 | 0–10 | 對齊：成功＝11 章卡片齊；方法＝架構→逐章填空 | 電梯簡報 |
| Block 1 | 10–25 | 全庫架構（A/B/C）＋每章一句「在解決什麼」 | 架構圖 |
| Block 2a | 25–61 | **Ch1–Ch4** 各 9 分：讀／問 → 填卡片 | 4 張卡 |
| Block 2b | 61–97 | **Ch5–Ch8** 各 9 分 | 4 張卡 |
| Block 2c | 97–133 | **Ch9–Ch11** 各 12 分（略深因較新） | 3 張卡 |
| Block 3 | 133–160 | 串成故事線：從「會用模型」到「安全／Agent」 | 7 分鐘講稿 |
| Block 4 | 160–180 | 自測 11 題（一章一題）＋標 3 個下次深挖章 | 會／模糊／不會 |

每章固定卡片格式（強制，逾時就填「待補」往下一章）：
1. 問題（一句）
2. 做法（一句）
3. 產出／實驗檔（README／pdf／ipynb）
4. 關鍵詞（1 個）

NotebookLM 策略：根 README 必加；逐章以該章 `README.md` 為主（不夠再加 pdf）。每章提示詞固定：
「只根據來源，用台灣繁體、媽媽說故事語氣，填：問題／做法／產出／1 關鍵詞。禁止實作細節與參數。」

## 5. 英語學習（配合使用者個性）

- 使用者傾向：**有真實需要才認真用**；啟動成本高就容易放棄。
- 主方法：真實郵件／回覆 → AI 協助潤成英文 → **手打第二遍**內化。
- 優化小步驟：先自己寫一版 → 請 AI 列出可套用句型與不自然處 → 每封信只留 1 句進累積本。
- 整理英語素材時：可幫使用者做成 Markdown／Google 文件結構，方便進 NotebookLM。
- **Google 文件（Docs）** 當 NotebookLM 來源較可能自動同步；GitHub 網址／上傳靜態檔通常不會自動更新。
- 目前無法在未接 Google API／自動化前，由 Agent 直接寫入使用者的 Drive；以約定檔＋整理稿降低手貼負擔。

## 6. 記憶方法偏好

- 優勢：對數字敏感、路線／空間關係強、筆記像心智圖、圖像聯想。
- **使用者指定的主系統（必須遵守）：**
  1. 以 **12345 為同一個畫面**（一次約五個），不是彼此無關的分立站點。
  2. **以 3 為主錨**，先聯想相鄰的 **2 與 4**；再 **1↔2**、**4↔5**。
  3. 空間位置要對應數字關係（例如 2 在 3「上面／最接近」、1 在 2 上、4 當方向／箭頭承載 3、5 在 4 下方等），以便「問幾號就能從畫面定位」。
  4. 11 個關鍵詞拆成：**畫面一 Ch1–5**、**畫面二 Ch6–10**（8 當該組的「3」主錨）、**Ch11 接在畫面二**。
- 長單字才用字母拆圖；工具保持低摩擦。
- 範例（Ch1–5，使用者認可）：3 編輯＝冰箱改價 → 上為 2 提示燈 → 燈上 1 微調鈕 → 冰箱站在 4 推理方向線 → 線下 5 浮水印水灘。

## 7. 回覆風格

- 直接、精簡；長答先給結論。
- 少用整句粗體刷屏。
- 技術概念優先用使用者已聽過的比喻延續（訓練／label／Skill vs 訓練等）。
- 使用者說「都可以／沒想法」時，由 Agent **選一條路徑並說明順序**，不要丟回二選一僵住。
- **教學模式（現行，重要）：關卡制＋百分比；提問服務於過關，不無限延伸。**
  - 每次回覆盡量標明：**目前關卡、本關 %、過關條件**。
  - 一關內最多約 **3 道決策題**；題目結束必須給「本關完成／未完成」結算，不得無止境追問。
  - 仍可用短題維持優化感，但要接已知情境；認知跳躍太大時立刻降級出題。
  - 興趣或成就感下降時：先結算進度，再開下一關，不要繼續問。
