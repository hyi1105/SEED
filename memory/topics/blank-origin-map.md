# 空白起源地圖：從空白理解整套系統

## 一句話

把丟進來的任何系統（連結、檔、程式、整套、AI 抓的）變成「從空白長出來」的教學：每個空白為什麼存在、代表什麼、流程怎麼跑；最後列出幾張表／每表空白，並可拖空白看關聯（起源地圖）。

## 核心隱喻：空白

- **空白**＝畫面／表單上的欄位（姓名、日期、狀態、意見…），以及讓流程轉彎的按鈕（退回、撤回）
- 人看不懂系統時，先別講資料庫；先問：**這個空白是因為誰、為了什麼事才出現的？**
- 從「一片空白」聽到完整需求，空白一個個長出來；跑完流程後，所有空白都在最後一張圖上

## 學習路徑（產品要給的體驗）

1. **丟進來** — 連結／檔案／程式碼／整系統／AI 擷取（先 Web）
2. **聽／還原** — 用對話或腳本還原「需求一句 → 空白一組」
3. **起源旁白** — 每個空白掛一句：因為你說「…」，所以需要「…」
4. **漸進拼圖** — 空舞台分區，一小撮一小撮長「名稱＋一句用途」（見下節）
5. **跑流程** — 申請 → 一簽 → 二簽 → 不同意退回改資料… 從頭到尾
6. **收斂清單** — 這個系統有幾張表？每張表有哪些空白？
7. **起源地圖** — 拖空白、看連線；結束停在最後完整圖
8. **真實驗證** — 模型／拼圖走完，再連真實畫面或流程演示

## 導覽節奏：漸進拼圖（四合院式）

> 參考的是節奏，不是主題。參考相簿：https://photos.app.goo.gl/ARjDdXCuyPNYhSiP8  
> （3D 一塊塊長出＋巨大標籤綁空間＋字幕講用途）

### 要

| # | 規則 |
|---|---|
| 1 | **先空舞台**，不要一次攤開全部名稱 |
| 2 | **分區**：申請端／處理中段／結案／權限／產出物 |
| 3 | 每步只長一小撮「**名稱＋一句用途**」 |
| 4 | 先問「下一塊該長什麼／誰用／為什麼需要」，**答對才長出** |
| 5 | 名稱**永遠掛在所屬區塊上** |
| 6 | 模型走完後，再連到**真實畫面／流程驗證** |

### 不要

- 長篇一次講完
- 只有測驗、沒有空間結構
- 一開始就丟完整 ER／選單

### 完成定義

新手能指著拼圖說出：有哪些名稱、各在哪一區、誰能動、用來完成什麼需求。

### 與「空白起源」怎麼疊

- 空白／按鈕＝拼圖上會長出來的「名稱」
- 起源旁白＝問答閘門裡的「為什麼需要」
- 五分區＝名稱釘死的空間；拖地圖時也不打散分區語意

## 請假故事線（示範腳本）

用來驗證「聽需求長空白」，可做成第三套系統包（請假），與離職／催收並列：

```
使用者：我要請假系統 → 姓名、電話、最後一天
系統：申請區出現三個空白（申請人填）

使用者：主管要簽
系統：第一簽核區：簽核人姓名、日期、狀態、意見

使用者：HR 要處理
系統：第二簽核區：同上四個空白

使用者：主管不同意可以撤回
系統：出現「退回／撤回」按鈕；一簽不通過 → 退回 → 可改資料再送
```

結束時應能回答：

- 表有幾張（例如：請假主檔、簽核歷程…；以實際還原為準）
- 每張表的空白清單與起源句
- 流程怎麼走、按鈕在什麼條件出現

## 資料原則

- 仍走 **Walkthrough JSON**（Schema + Skill）；畫面只是另一種 `render`
- 建議在欄位／步驟上加可選欄位，例如：
  - `origin`：這句需求／來源（「主管要簽」）
  - `meaning`：人話意義（「第一關同意與否」）
  - `appears_when`：何時出現在畫面上
- 按鈕／動作也是「空白家族」：不是只有 input，退回鍵也要有起源

## 決定／偏好

- 先 Web；教學優先於一次做完所有匯入器
- 空白起源＝主軸隱喻；地圖可拖＝「寫原圖」的操作感
- 導覽節奏＝**漸進拼圖（四合院式）**：空舞台 → 問答閘門 → 名稱釘區 → 真實驗證
- 示範優先請假對話線；參考相簿只借節奏
