# 跨專案怎麼說：四合院式漸進拼圖學習

> 把「影片那種記法」講給其他專案／Agent 時用這份。目標是讓對方懂**要學什麼節奏**，不是要抄四合院主題。

## 一句話（電梯版）

不要一次丟完整系統；像蓋院子一樣，**一塊一塊長出來**——名稱與用途綁在空間上，**先問再長出**，用來上手一堆陌生名稱、用途、需求。

## 30 秒版（口頭／聊天）

```text
我想用一種「漸進拼圖」的方式教陌生系統，參考一支四合院解說短影音：
不是一開始秀完整架構，而是從空地開始，每講一個部位就長出一塊，
並用大標籤把「名稱」釘在它該在的位置，旁邊講「用途」。

套到系統上：先長申請欄位 → 再長催收／結案欄位 → 再長權限牆 → 最後收成可播放的系統包。
中間用問答：先猜下一塊該長什麼，答對才長出來。
這樣記一堆陌生名稱、用途、需求會比較上手。
```

## 貼給其他專案 Agent 的 brief（可直接複製）

```text
【學習／導覽設計偏好：漸進拼圖（四合院式）】

參考節奏（不是要做四合院主題）：
https://photos.app.goo.gl/ARjDdXCuyPNYhSiP8
（手機錄的 YouTube Shorts：3D 模型一塊塊長出＋巨大標籤綁空間＋字幕講用途）

請做成：
1. 先空舞台／空地圖，不要一次攤開全部名稱
2. 分區（例如：申請端／處理中段／結案／權限／產出物）
3. 每一步只長一小撮「名稱＋一句用途」
4. 先問「下一塊該長什麼／誰用／為什麼需要」，答對才長出；答錯可重選
5. 名稱永遠掛在所屬區塊上（空間記憶）
6. 抽象模型走完後，再連到真實畫面／真實流程驗證

不要做成：
- 長篇說明文一次講完
- 只有測驗、沒有結構長出來
- 一開始就丟完整 ER／完整選單

完成定義：
新手能指著拼圖說出：有哪些名稱、各在哪一區、誰能動、用來完成什麼需求。
```

## 若對方問「這跟一般 onboarding 差在哪」

| 一般 | 漸進拼圖 |
|---|---|
| 一次給完整架構圖 | 從空地累積到完整 |
| 名稱列在文件裡 | 名稱釘在空間位置上 |
| 看完再測驗 | **先猜再長出**（測驗驅動揭曉） |
| 教功能點擊路徑 | 教**名稱 × 用途 × 需求**怎麼長在一起 |
