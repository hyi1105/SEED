# 構想：空白起源地圖（從空白理解整套系統）

## 摘要

要把「丟進來的任何東西」（連結、檔案、系統程式碼、整套系統、AI 幫抓下來的畫面／結構）轉成**人讀得懂、教得會、問得答**的東西。核心隱喻是**空白**（欄位／按鈕）：從一片空白開始，用對話還原「為什麼需要這個空白」，一路走到所有空白都出現、流程跑完、停在最後一張圖；最後能拖這些空白看關聯地圖（起源地圖）。

## 重點

### 輸入（什麼都能丟）

- 連結、檔案、系統程式碼、整套系統
- AI 幫忙擷取／還原的系統
- （使用者說之後會再貼連結；本場尚未附上）

### 輸出（變成可學）

- **教**：為什麼有這個空白、實際意義是什麼
- **聊／答**：用對話方式講清楚
- **跑流程**：怎麼走完整套流程
- **收斂**：這個系統有幾張表、每張表有哪些空白（沒有空白＝沒有欄位的表也要說清楚）
- **地圖**：可拖曳空白看連線（起源／關聯圖）；結束停在最後一張完整圖

### 請假單例子（逐步長出空白）

| 使用者說的需求 | 系統因此多出的空白／行為 |
|---|---|
| 要做請假系統：姓名、電話、最後一天 | 申請人區：姓名、電話、最後一天 |
| 要給主管簽 | 第一簽核人：姓名、日期、狀態、意見 |
| 還要給 HR 處理 | 第二簽核人：姓名、日期、狀態、意見 |
| 主管不同意可以撤回 | 按鈕：第一簽不通過時可退回；退回後可改資料再送 |

重點不是先畫 ER，而是：**聽一句話 → 知道多哪些空白／按鈕 → 說清楚為什麼**。

### 與既有產品線的關係

| 既有 | 本場補上的缺口 |
|---|---|
| 導引（需求對話 → 欄位 → 權限 → 成檔） | 強調「每個空白的**起源故事**」：因為哪句需求才出現 |
| 情境 walkthrough（角色×情境×步驟高亮） | 結束要能回答「幾張表／每表空白」＋停在最後完整圖 |
| 地圖儀表板（可拖） | 拖的是**空白**本身，看關聯＝寫「起源地圖」 |
| 多來源 → Walkthrough JSON | 連結／檔案／程式／整系統／AI 擷取都進同一模型 |

## 決定／偏好

- 先做 Web
- 教學主軸＝**從空白到整套**：空白為何存在 → 意義 → 流程 → 表結構 → 可拖地圖
- 示範可用請假（與離職、催收並列）；本場以請假對話為故事線
- 仍統一吃 Walkthrough JSON；不另發明第三套資料語言
