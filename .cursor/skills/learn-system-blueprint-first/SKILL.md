# 學習系統：藍圖先、欄位後（由大到小）

使用者**主要在學習**，不是要你重做產品。系統可能已畫在別處（iAgent、截圖、程式）。

## 何時使用

- 「教我學這套系統」「我畫好了但一次看不完」
- 「先藍圖／總覽，再進欄位」
- 「跟 SEED Show 一樣：下一步推進」

## 節奏（務必）

1. **禁止開場空白**：不要一開始攤一堆沒意義的空欄位。
2. **第一屏＝故事舞台／藍圖**：最好用**泳道＋橢圓流程**（像偽代碼的圖）。位置有意義——例如左到右四條線＝四張表；節點畫在「正在發生」的那一格。抉擇＝可分左右的橢圓／菱形。
3. **情緒價值**：像短片／視覺小說，每步只發生一件事，讓人想按下一步；整體畫面感優先於轉場細節。
4. **外型一致**：舞台上的區塊與後面真表單同一語彙；不要前面按鈕、後面表單兩種皮膚。
5. **再進細節**：點某個橢圓／進某一張，才長出欄位並講「為什麼需要」。
6. **推進**：上一步／下一步；關鍵分歧才給選項。不要開場考試、不要長篇一次講完。

詳見 `memory/topics/story-swimlane-learn.md`。

## 每一層講清楚

| 層 | 要講 |
|---|---|
| 大 | 幾張表／區塊、誰連誰、做完一件事經過哪幾張 |
| 中 | 進某一張時，有哪些欄位名稱（字要看得見） |
| 小 | 某欄位為什麼存在、誰填、跟上下張怎麼連 |

## 完成定義

使用者能指著畫面說：有幾張大表、怎麼連、某張重要欄位各完成什麼。

## 輸出方式

- 用對話＋簡單紙本／圖示示意即可；先藍圖，等使用者說「下一步」再往下一層。
- 若目標是 SEED 播放器 JSON，另讀 `docs/walkthrough/SKILL.md`（產包契約）；本 Skill 管**教學節奏**。

## 可貼給其他 Agent 的短版

```text
教我學這套已畫好的系統：先藍圖（幾張表、誰連誰，同一屏看完），外型前後一致；不要先丟空白欄位。再進單張講欄位。用上一步／下一步，由大到小。
```

更完整可貼版見 `memory/topics/learn-system-prompt.md`。
